# SQL 12 — JSON, Dates and Text

Real data is semi-structured and full of timestamps. PostgreSQL stores JSON
as `jsonb`, does date arithmetic with `interval`, and processes text with
ordinary functions. The types are real: a bad document or a bad date fails
on write, not later.

Do not build SQL by concatenating user text. Bind `$1`, `$2`, and so on in
the driver. That is what prevents SQL injection.

## ->> returns text, -> returns jsonb

`jsonb` is binary JSON. It is indexable, and it rejects text that is not
JSON. Use it for genuinely schemaless parts, and real columns for anything
you filter, join, or constrain. `->>` returns text and strips quotes.
`->` returns `jsonb`, quotes and all. A missing key is NULL, not an error,
so a typo hides. Paths are keys, not `$.user`: `payload ->> 'user'`, and
`payload -> 'meta' ->> 'ip'` to step into an object. Printed `jsonb` has
spaces after `:` and `,`.

```sql file=n01.sql
CREATE TABLE event (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  payload jsonb
);
-- expect-error
INSERT INTO event (payload) VALUES ('not json');
INSERT INTO event (payload) VALUES
  ('{"user":"ada","action":"login","meta":{"ip":"10.0.0.1","tags":["a","b"]}}'),
  ('{"user":"bob","action":"buy","amount":25.5,"meta":{"ip":"10.0.0.2","tags":[]}}'),
  ('{"user":"ada","action":"buy","amount":10,"meta":{"ip":"10.0.0.1","tags":["c"]}}');
.headers on
SELECT id, payload ->> 'user' AS who, payload -> 'meta' ->> 'ip' AS ip,
       payload -> 'meta' -> 'tags' AS tags
FROM event ORDER BY id;
SELECT id, payload ->> 'nope' AS missing FROM event WHERE id = 1;
```

```text output
Error: invalid input syntax for type json
id|who|ip|tags
1|ada|10.0.0.1|["a", "b"]
2|bob|10.0.0.2|[]
3|ada|10.0.0.1|["c"]
id|missing
1|
```

## JSON fields aggregate like columns

`->>` yields text. Cast it before `sum`. Filter on `action` the same way
you filter any other column. `GROUP BY` may use the select-list alias.

```sql file=n02.sql
CREATE TABLE event (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  payload jsonb
);
INSERT INTO event (payload) VALUES
  ('{"user":"ada","action":"login","meta":{"ip":"10.0.0.1","tags":["a","b"]}}'),
  ('{"user":"bob","action":"buy","amount":25.5,"meta":{"ip":"10.0.0.2","tags":[]}}'),
  ('{"user":"ada","action":"buy","amount":10,"meta":{"ip":"10.0.0.1","tags":["c"]}}');
.headers on
SELECT payload ->> 'user' AS who, sum((payload ->> 'amount')::numeric) AS spent
FROM event WHERE payload ->> 'action' = 'buy' GROUP BY who ORDER BY who;
```

```text output
who|spent
ada|10
bob|25.5
```

## jsonb_array_elements and jsonb_each expand a document

`jsonb_array_elements` turns a JSON array into rows of `jsonb`.
`WITH ORDINALITY` adds the position, starting at 1, so the tags stay in
array order. An empty array adds nothing, so bob's event disappears.
`#>> '{}'` reads a scalar as text. `jsonb_each` does the same for an
object: one row per key. A scalar `jsonb` value still prints with quotes;
an array prints as JSON.

```sql file=n03.sql
CREATE TABLE event (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  payload jsonb
);
INSERT INTO event (payload) VALUES
  ('{"user":"ada","action":"login","meta":{"ip":"10.0.0.1","tags":["a","b"]}}'),
  ('{"user":"bob","action":"buy","amount":25.5,"meta":{"ip":"10.0.0.2","tags":[]}}'),
  ('{"user":"ada","action":"buy","amount":10,"meta":{"ip":"10.0.0.1","tags":["c"]}}');
.headers on
SELECT e.id, t.elem #>> '{}' AS tag
FROM event e
CROSS JOIN LATERAL jsonb_array_elements(e.payload -> 'meta' -> 'tags')
  WITH ORDINALITY AS t(elem, ord)
ORDER BY e.id, t.ord;
SELECT e.id, kv.key, kv.value
FROM event e
CROSS JOIN LATERAL jsonb_each(e.payload -> 'meta') AS kv
ORDER BY e.id, kv.key;
```

```text output
id|tag
1|a
1|b
3|c
id|key|value
1|ip|"10.0.0.1"
1|tags|["a", "b"]
2|ip|"10.0.0.2"
2|tags|[]
3|ip|"10.0.0.1"
3|tags|["c"]
```

## jsonb_build_object and jsonb_agg build documents

`jsonb_build_object` builds one object per group. Keys come out sorted,
because `jsonb` does not preserve object key order. `jsonb_agg` collects
values, including duplicates. Give it `ORDER BY` or the array order is
undefined.

```sql file=n04.sql
CREATE TABLE event (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  payload jsonb
);
INSERT INTO event (payload) VALUES
  ('{"user":"ada","action":"login","meta":{"ip":"10.0.0.1","tags":["a","b"]}}'),
  ('{"user":"bob","action":"buy","amount":25.5,"meta":{"ip":"10.0.0.2","tags":[]}}'),
  ('{"user":"ada","action":"buy","amount":10,"meta":{"ip":"10.0.0.1","tags":["c"]}}');
.headers on
SELECT jsonb_build_object('user', payload ->> 'user', 'n', count(*)) AS doc
FROM event GROUP BY payload ->> 'user' ORDER BY 1;
SELECT jsonb_agg(payload ->> 'user' ORDER BY id) AS users FROM event;
```

```text output
doc
{"n": 1, "user": "bob"}
{"n": 2, "user": "ada"}
users
["ada", "bob", "ada"]
```

## jsonb_set and - edit a document

`jsonb_set` adds or replaces a path. The third argument is `jsonb`, not
text, so a number is `'2'::jsonb` or just `2` in a jsonb literal. The `-`
operator deletes one key. Both return a new value. They do not update a
table unless you `UPDATE` with the result.

```sql file=n05.sql
.headers on
SELECT jsonb_set('{"a":1}'::jsonb, '{b}', '2') AS added,
       '{"a":1,"b":2}'::jsonb - 'a' AS removed;
```

```text output
added|removed
{"a": 1, "b": 2}|{"b": 2}
```

## An expression index covers a JSON path

The index is on `(payload ->> 'user')`, the same expression the `WHERE`
uses. Parentheses around the expression are required. A btree on that
expression serves equality. A GIN index on the whole `jsonb` serves
containment (`@>`), which is a different predicate. Two rows are cheaper
to scan than to probe, so this table has 5000. `ANALYZE` updates the
statistics the planner reads. `EXPLAIN (COSTS OFF)` drops the cost numbers
and leaves the node type.

```sql file=n06.sql
CREATE TABLE event (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  payload jsonb
);
INSERT INTO event (payload)
SELECT jsonb_build_object('user', CASE WHEN i = 1 THEN 'ada' ELSE 'bob' END, 'action', 'buy')
FROM generate_series(1, 5000) AS i;
ANALYZE event;
EXPLAIN (COSTS OFF) SELECT id FROM event WHERE payload ->> 'user' = 'ada';
CREATE INDEX event_user ON event ((payload ->> 'user'));
ANALYZE event;
EXPLAIN (COSTS OFF) SELECT id FROM event WHERE payload ->> 'user' = 'ada';
```

```text output
Seq Scan on event
  Filter: ((payload ->> 'user'::text) = 'ada'::text)
Index Scan using event_user on event
  Index Cond: ((payload ->> 'user'::text) = 'ada'::text)
```

## interval arithmetic returns a timestamp, and months clamp

`date` and `timestamp` are real types. `date + interval` yields
`timestamp`, which is why the time appears. Cast back to `date` when you
want a date. `date + integer` stays a date and means days.
`date '2024-01-31' + interval '1 month'` is 29 February 2024, not 2 March:
the day clamps to the end of the month. The last day of the month that
contains a date is `date_trunc('month', d) + interval '1 month' - interval '1 day'`.
Store UTC in `timestamptz` when the instant matters, and convert at the
edge. These literals do not move when you rerun the script.

```sql file=n07.sql
.headers on
SELECT date '2024-03-15' AS d,
       (timestamp '2024-03-15 13:45:10')::time AS t,
       timestamp '2024-03-15 13:45:10' AS dt;
SELECT date '2024-03-15' + interval '1 month' AS plus_month,
       (date '2024-01-31' + interval '1 month')::date AS jan31_plus_month,
       (date '2024-03-15' - interval '7 days')::date AS minus_week,
       (date_trunc('month', date '2024-03-15') + interval '1 month' - interval '1 day')::date AS month_end;
```

```text output
d|t|dt
2024-03-15|13:45:10|2024-03-15 13:45:10
plus_month|jan31_plus_month|minus_week|month_end
2024-04-15 00:00:00|2024-02-29|2024-03-08|2024-03-31
```

## to_char and extract pull pieces out of a date

`to_char` formats. `YYYY` is the year, `MM` the month, `DDD` the day of
the year, zero-padded. `extract(dow FROM d)` is the weekday, 0 for Sunday,
so 15 March 2024 is 5. Subtracting two `date` values is an integer day
count, not inclusive of both ends. `extract(epoch FROM timestamp ...)` is
seconds since 1970-01-01 00:00:00 UTC. Adding that many seconds to
`timestamp 'epoch'` rebuilds the timestamp.

```sql file=n08.sql
.headers on
SELECT to_char(date '2024-03-15', 'YYYY') AS year,
       to_char(date '2024-03-15', 'MM') AS month,
       extract(dow FROM date '2024-03-15')::int AS weekday,
       to_char(date '2024-03-15', 'DDD') AS day_of_year;
SELECT (date '2024-03-15' - date '2024-01-01') AS days_between,
       extract(epoch FROM timestamp '2024-01-01 00:00:00')::bigint AS epoch,
       timestamp 'epoch' + 1704067200 * interval '1 second' AS back;
```

```text output
year|month|weekday|day_of_year
2024|03|5|075
days_between|epoch|back
74|1704067200|2024-01-01 00:00:00
```

## Group by the month text, and bound a window with dates

`to_char(at, 'YYYY-MM')` is the month key. The last-7-days test is
`at >= date '2024-03-15' - 7`. Subtracting an integer from a `date` keeps
the `date` type. Pin "today" to a literal when the result has to be
repeatable. `current_date` would move.

```sql file=n09.sql
CREATE TABLE login (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  at date NOT NULL
);
INSERT INTO login (at) VALUES
  (date '2024-03-01'), (date '2024-03-10'), (date '2024-03-14'), (date '2024-04-02');
.headers on
SELECT to_char(at, 'YYYY-MM') AS month, count(*) AS logins
FROM login GROUP BY month ORDER BY month;
SELECT count(*) AS last7 FROM login
WHERE at >= date '2024-03-15' - 7 AND at <= date '2024-03-15';
```

```text output
month|logins
2024-03|3
2024-04|1
last7
2
```

## Text functions slice, fold, and measure

`substr` is 1-based. `position(needle IN haystack)` returns the first
match, or 0. `lower` and `upper` follow the database locale, so `Ä`
becomes `ä` here. `length` counts characters. `octet_length` counts bytes,
and `é` is two bytes in UTF-8.

```sql file=n10.sql
.headers on
SELECT substr('abcdef', 2, 3) AS slice,
       position('o' IN 'hello world') AS pos,
       replace('a-b-c', '-', '/') AS swapped,
       trim('  pad  ') AS trimmed,
       ltrim('xxabc', 'x') AS stripped,
       lower('ÄB') AS folded,
       upper('ab') AS up,
       length('héllo') AS chars,
       octet_length('héllo') AS bytes;
```

```text output
slice|pos|swapped|trimmed|stripped|folded|up|chars|bytes
bcd|5|a/b/c|pad|abc|äb|AB|5|6
```

## to_char, rpad and to_hex format values

`FM` in a `to_char` template drops the leading space reserved for a sign,
so `FM00000` is five digits. Without `FM`, `00000` prints a space in front.
`rpad` pads on the right. `FM990.00` keeps two decimal places. `to_hex`
is lowercase hex. The same job in application code is fine; this is for
shaping a result set.

```sql file=n11.sql
.headers on
SELECT to_char(42, 'FM00000') AS padded,
       rpad('ab', 6) AS wide,
       to_char(3.14159, 'FM990.00') AS rounded,
       to_hex(255) AS hex;
```

```text output
padded|wide|rounded|hex
00042|ab    |3.14|ff
```

## LIKE is case-sensitive; ILIKE is not

`'a' = 'A'` is false. `LIKE` is case-sensitive. `ILIKE` folds case.
Ordering follows the database collation (`en_US.utf8` on this server),
which is not raw byte order. Equality does not fold. Booleans print `t`
and `f`.

```sql file=n12.sql
.headers on
SELECT 'apple' < 'banana' AS alpha,
       'a' = 'A' AS same,
       'abc' LIKE 'A%' AS like_cs,
       'abc' ILIKE 'A%' AS ilike;
```

```text output
alpha|same|like_cs|ilike
t|f|f|t
```

## A recursive CTE splits a comma list

The anchor holds the unsplit text. Each step takes the characters before
the next comma and leaves the rest. `position` finds the comma. Lesson 13
is the full story of recursive queries. The empty piece before the first
comma is discarded. The anchor is cast to `text` so the step's `substr`
result has a type to match.

```sql file=n13.sql
.headers on
SELECT word FROM (
  WITH RECURSIVE parts(word, rest) AS (
    SELECT ''::text, 'red,green,blue,'
    UNION ALL
    SELECT substr(rest, 1, position(',' IN rest) - 1),
           substr(rest, position(',' IN rest) + 1)
    FROM parts WHERE rest <> ''
  )
  SELECT word FROM parts WHERE word <> ''
) s;
```

```text output
word
red
green
blue
```

```sql file=solution.sql
CREATE TABLE order_doc (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  doc jsonb
);
INSERT INTO order_doc (doc) VALUES
  ('{"customer":"ada","placed":"2024-03-02","items":[{"sku":"A","qty":2,"price":5},{"sku":"B","qty":1,"price":20}]}'),
  ('{"customer":"bob","placed":"2024-03-20","items":[{"sku":"A","qty":5,"price":5}]}'),
  ('{"customer":"ada","placed":"2024-04-01","items":[{"sku":"C","qty":3,"price":4}]}');

CREATE VIEW q1 AS
  SELECT o.id,
         sum((item.value ->> 'qty')::integer * (item.value ->> 'price')::integer) AS total
  FROM order_doc o
  CROSS JOIN LATERAL jsonb_array_elements(o.doc -> 'items') AS item(value)
  GROUP BY o.id
  ORDER BY o.id;
CREATE VIEW q2 AS
  SELECT o.doc ->> 'customer' AS customer,
         sum((item.value ->> 'qty')::integer * (item.value ->> 'price')::integer) AS spent
  FROM order_doc o
  CROSS JOIN LATERAL jsonb_array_elements(o.doc -> 'items') AS item(value)
  GROUP BY customer
  ORDER BY customer;
CREATE VIEW q3 AS
  SELECT to_char((doc ->> 'placed')::date, 'YYYY-MM') AS month, count(*) AS orders
  FROM order_doc GROUP BY month ORDER BY month;
CREATE VIEW q4 AS
  SELECT id, (doc ->> 'placed')::date + 30 AS due FROM order_doc ORDER BY id;
CREATE VIEW q5 AS
  SELECT string_agg(DISTINCT item.value ->> 'sku', ',' ORDER BY item.value ->> 'sku') AS skus
  FROM order_doc o
  CROSS JOIN LATERAL jsonb_array_elements(o.doc -> 'items') AS item(value);

CREATE TABLE t (name text, ok boolean CHECK (ok));
INSERT INTO t VALUES ('q1', (SELECT string_agg(id::text || ':' || total::text, ',' ORDER BY id) FROM q1) IS NOT DISTINCT FROM '1:30,2:25,3:12');
INSERT INTO t VALUES ('q2', (SELECT string_agg(customer || '=' || spent::text, ',' ORDER BY customer) FROM q2) IS NOT DISTINCT FROM 'ada=42,bob=25');
INSERT INTO t VALUES ('q3', (SELECT string_agg(month || '=' || orders::text, ',' ORDER BY month) FROM q3) IS NOT DISTINCT FROM '2024-03=2,2024-04=1');
INSERT INTO t VALUES ('q4', (SELECT string_agg(id::text || ':' || due::text, ',' ORDER BY id) FROM q4) IS NOT DISTINCT FROM '1:2024-04-01,2:2024-04-19,3:2024-05-01');
INSERT INTO t VALUES ('q5', (SELECT skus FROM q5) IS NOT DISTINCT FROM 'A,B,C');
SELECT 'PASS ' || name FROM t ORDER BY name;
```
