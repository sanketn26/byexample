# SQL 14 — Capstone: A Bookstore, End to End

Everything in one place: a schema with constraints, a trigger that guards
stock, and reports built from joins, aggregates, windows, and CTEs. Money
is integer cents, so sums stay exact. `numeric(10,2)` is the alternative
when the unit is not cents. Do not use `float`. Foreign keys are enforced
without a switch.

Migrations are numbered scripts that only move forward. Record which have
run (a `schema_migrations` table) and never edit one that has already been
applied. Snapshot `unit_price_cents` onto the order line. If you join back
to `book.price_cents`, old orders change when the catalogue does. Decide
what "revenue" means once (here: not cancelled) and put that filter in a
view so every report agrees. Reports that join many tables belong in views
or CTEs with names that say what they mean. Copy-pasted subqueries drift
apart. A SQL test is a query with a known answer on a small fixed dataset,
like the exercises in this track.

## The schema is the first migration

Ids are `GENERATED BY DEFAULT AS IDENTITY`, so the seed can name them and
a later insert can omit them. Prices and stock are integers, with checks.
`orders.status` is a closed list. `placed` and `joined` are `date`.
`order_line` snapshots the price and cascades when the order is deleted.
PostgreSQL does not index a foreign key for you. The two indexes cover
those columns. Primary keys and the unique title create their own indexes;
the catalog query below hides those and lists tables plus the two you added.

```sql file=n01.sql
CREATE TABLE customer (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  country text NOT NULL,
  joined date NOT NULL
);
CREATE TABLE book (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL UNIQUE,
  genre text NOT NULL,
  price_cents integer NOT NULL CHECK (price_cents > 0),
  stock integer NOT NULL DEFAULT 0 CHECK (stock >= 0)
);
CREATE TABLE orders (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customer (id),
  placed date NOT NULL,
  status text NOT NULL CHECK (status IN ('open', 'paid', 'shipped', 'cancelled'))
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id) ON DELETE CASCADE,
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL CHECK (qty > 0),
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
CREATE INDEX order_customer ON orders (customer_id);
CREATE INDEX line_book ON order_line (book_id);
.headers on
SELECT name FROM (
  SELECT tablename AS name FROM pg_tables WHERE schemaname = 'public'
  UNION ALL
  SELECT indexname FROM pg_indexes
  WHERE schemaname = 'public'
    AND indexname NOT LIKE '%\_pkey' ESCAPE '\'
    AND indexname NOT LIKE '%\_key' ESCAPE '\'
) s ORDER BY name;
```

```text output
book
customer
line_book
order_customer
order_line
orders
```

## The stock trigger plus a CHECK blocks overselling

The trigger subtracts `NEW.qty` on every insert, including cancelled orders.
`CONSTRAINT stock_nonneg` rejects the update when the shelf does not have
99 copies, and that failure rolls the insert back. Neuromancer stays at 2:
the catalogue started at 3, and one copy was already sold. The error names
the constraint, not the trigger. The trigger is what issued the `UPDATE`.

```sql file=n02.sql
CREATE TABLE customer (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  country text NOT NULL,
  joined date NOT NULL
);
CREATE TABLE book (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL UNIQUE,
  genre text NOT NULL,
  price_cents integer NOT NULL CHECK (price_cents > 0),
  stock integer NOT NULL DEFAULT 0 CONSTRAINT stock_nonneg CHECK (stock >= 0)
);
CREATE TABLE orders (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customer (id),
  placed date NOT NULL,
  status text NOT NULL CHECK (status IN ('open', 'paid', 'shipped', 'cancelled'))
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id) ON DELETE CASCADE,
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL CHECK (qty > 0),
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
CREATE FUNCTION line_takes_stock() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE book SET stock = stock - NEW.qty WHERE id = NEW.book_id;
  RETURN NEW;
END;
$$;
CREATE TRIGGER line_takes_stock
AFTER INSERT ON order_line
FOR EACH ROW
EXECUTE FUNCTION line_takes_stock();

  (3, 'Cy',  'US', date '2024-02-14'), (4, 'Di',  'DE', date '2024-03-01');
INSERT INTO book (id, title, genre, price_cents, stock) VALUES
  (1, 'Dune', 'scifi', 1200, 10), (2, 'Emma', 'classic', 800, 5),
  (3, 'Hobbit', 'fantasy', 1000, 8), (4, 'Neuromancer', 'scifi', 900, 3);
INSERT INTO orders (id, customer_id, placed, status) VALUES
  (1, 1, date '2024-01-05', 'shipped'), (2, 1, date '2024-02-11', 'shipped'),
  (3, 2, date '2024-02-20', 'paid'), (4, 3, date '2024-03-03', 'shipped'),
```

## Revenue by genre skips cancelled orders

`round(sum(...) / 100.0, 1)` is dollars to one decimal. Keep the cents as
integers until that edge. The status test is in `WHERE` because this is an
inner join: cancelled lines should vanish, not appear as NULL. Sci-fi leads
because Dune was bought twice and not cancelled, and the cancelled
five-copy order is excluded.

```sql file=n03.sql
CREATE TABLE customer (
  id integer PRIMARY KEY,
  name text NOT NULL,
  country text NOT NULL,
  joined date NOT NULL
);
CREATE TABLE book (
  id integer PRIMARY KEY,
  title text NOT NULL UNIQUE,
  genre text NOT NULL,
  price_cents integer NOT NULL CHECK (price_cents > 0)
);
CREATE TABLE orders (
  id integer PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customer (id),
  placed date NOT NULL,
  status text NOT NULL CHECK (status IN ('open', 'paid', 'shipped', 'cancelled'))
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id),
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL,
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
INSERT INTO customer VALUES
  (1, 'Ada', 'UK', date '2023-01-10'), (2, 'Bob', 'US', date '2023-05-02'),
  (3, 'Cy', 'US', date '2024-02-14'), (4, 'Di', 'DE', date '2024-03-01');
INSERT INTO book (id, title, genre, price_cents) VALUES
  (1, 'Dune', 'scifi', 1200), (2, 'Emma', 'classic', 800),
  (3, 'Hobbit', 'fantasy', 1000), (4, 'Neuromancer', 'scifi', 900);
INSERT INTO orders VALUES
  (1, 1, date '2024-01-05', 'shipped'), (2, 1, date '2024-02-11', 'shipped'),
  (3, 2, date '2024-02-20', 'paid'), (4, 3, date '2024-03-03', 'shipped'),
  (5, 2, date '2024-03-15', 'cancelled'), (6, 4, date '2024-03-20', 'open');
INSERT INTO order_line VALUES
  (1, 1, 1, 1200), (1, 2, 2, 800), (2, 3, 1, 1000), (3, 1, 2, 1200),
  (4, 4, 1, 900), (4, 3, 1, 1000), (5, 1, 5, 1200), (6, 2, 1, 800);
.headers on
SELECT b.genre, round(sum(l.qty * l.unit_price_cents) / 100.0, 1) AS revenue
FROM order_line l
JOIN orders o ON o.id = l.order_id
JOIN book b ON b.id = l.book_id
WHERE o.status <> 'cancelled'
GROUP BY b.genre
ORDER BY revenue DESC, b.genre;
```

## Rank customers by spend, and show their share

The status filter is in the `ON` clause. A `WHERE` on `o.status` would drop
a customer whose orders were all cancelled, and anyone with no orders.
`coalesce` makes a missing sum zero. `GROUP BY c.id` is enough for
`c.name`, because `id` is the primary key. `rank` is the place. The window
`sum` over the whole result is the denominator of the share. `round(..., 1)`
keeps one decimal.

```sql file=n04.sql
CREATE TABLE customer (
  id integer PRIMARY KEY,
  name text NOT NULL,
  country text NOT NULL,
  joined date NOT NULL
);
CREATE TABLE book (
  id integer PRIMARY KEY,
  title text NOT NULL,
  genre text NOT NULL,
  price_cents integer NOT NULL
);
CREATE TABLE orders (
  id integer PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customer (id),
  placed date NOT NULL,
  status text NOT NULL
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id),
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL,
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
INSERT INTO customer VALUES
  (1, 'Ada', 'UK', date '2023-01-10'), (2, 'Bob', 'US', date '2023-05-02'),
  (3, 'Cy', 'US', date '2024-02-14'), (4, 'Di', 'DE', date '2024-03-01');
INSERT INTO book VALUES
  (1, 'Dune', 'scifi', 1200), (2, 'Emma', 'classic', 800),
  (3, 'Hobbit', 'fantasy', 1000), (4, 'Neuromancer', 'scifi', 900);
INSERT INTO orders VALUES
  (1, 1, date '2024-01-05', 'shipped'), (2, 1, date '2024-02-11', 'shipped'),
  (3, 2, date '2024-02-20', 'paid'), (4, 3, date '2024-03-03', 'shipped'),
  (5, 2, date '2024-03-15', 'cancelled'), (6, 4, date '2024-03-20', 'open');
INSERT INTO order_line VALUES
  (1, 1, 1, 1200), (1, 2, 2, 800), (2, 3, 1, 1000), (3, 1, 2, 1200),
  (4, 4, 1, 900), (4, 3, 1, 1000), (5, 1, 5, 1200), (6, 2, 1, 800);
.headers on
SELECT name, round(cents / 100.0, 1) AS spend,
       rank() OVER (ORDER BY cents DESC) AS place,
       round(100.0 * cents / sum(cents) OVER (), 1) AS pct
FROM (
  SELECT c.name, coalesce(sum(l.qty * l.unit_price_cents), 0) AS cents
  FROM customer c
  LEFT JOIN orders o ON o.customer_id = c.id AND o.status <> 'cancelled'
  LEFT JOIN order_line l ON l.order_id = o.id
  GROUP BY c.id
) spend
ORDER BY place, name;
```

## Top book per country is row_number in a partition

Sum units per country and title, then keep `rn = 1`. The tie-breaker is
the title. Cancelled orders are excluded in the join condition.

```sql file=n05.sql

INSERT INTO book VALUES
  (1, 'Dune', 'scifi', 1200), (2, 'Emma', 'classic', 800),
  (3, 'Hobbit', 'fantasy', 1000), (4, 'Neuromancer', 'scifi', 900);
INSERT INTO orders VALUES
  (1, 1, date '2024-01-05', 'shipped'), (2, 1, date '2024-02-11', 'shipped'),
  (3, 2, date '2024-02-20', 'paid'), (4, 3, date '2024-03-03', 'shipped'),
  (5, 2, date '2024-03-15', 'cancelled'), (6, 4, date '2024-03-20', 'open');
INSERT INTO order_line VALUES
  (1, 1, 1, 1200), (1, 2, 2, 800), (2, 3, 1, 1000), (3, 1, 2, 1200),
  (4, 4, 1, 900), (4, 3, 1, 1000), (5, 1, 5, 1200), (6, 2, 1, 800);
.headers on
SELECT country, title, units FROM (
  SELECT c.country, b.title, sum(l.qty) AS units,
         row_number() OVER (PARTITION BY c.country ORDER BY sum(l.qty) DESC, b.title) AS rn
  FROM order_line l
  JOIN orders o ON o.id = l.order_id AND o.status <> 'cancelled'
  JOIN customer c ON c.id = o.customer_id
  JOIN book b ON b.id = l.book_id
  GROUP BY c.country, b.id
) ranked
WHERE rn = 1
ORDER BY country;
```

## Month-over-month change is lag on the monthly sum

`to_char(placed, 'YYYY-MM')` is the month. `lag` is NULL for January, then
the difference against the previous month. March includes Di's open order
and excludes Bob's cancelled one. A NULL change prints as an empty field.

```sql file=n06.sql
CREATE TABLE orders (
  id integer PRIMARY KEY,
  placed date NOT NULL,
  status text NOT NULL
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id),
  book_id integer NOT NULL,
  qty integer NOT NULL,
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
INSERT INTO orders VALUES
  (1, date '2024-01-05', 'shipped'), (2, date '2024-02-11', 'shipped'),
  (3, date '2024-02-20', 'paid'), (4, date '2024-03-03', 'shipped'),
  (5, date '2024-03-15', 'cancelled'), (6, date '2024-03-20', 'open');
INSERT INTO order_line VALUES
  (1, 1, 1, 1200), (1, 2, 2, 800), (2, 3, 1, 1000), (3, 1, 2, 1200),
  (4, 4, 1, 900), (4, 3, 1, 1000), (5, 1, 5, 1200), (6, 2, 1, 800);
.headers on
SELECT month, cents, cents - lag(cents) OVER (ORDER BY month) AS change
FROM (
  SELECT to_char(o.placed, 'YYYY-MM') AS month,
         sum(l.qty * l.unit_price_cents) AS cents
  FROM orders o
  JOIN order_line l ON l.order_id = o.id
  WHERE o.status <> 'cancelled'
  GROUP BY month
) monthly
ORDER BY month;
```

## Restock compares stock with recent lines

The trigger has already reduced stock by every inserted line, cancelled or
not. The `HAVING` keeps books with 5 or fewer left. The date and status
tests sit on the orders join, not on the line, so a line still counts when
that join misses. Dune's recent total of 8 includes the cancelled order.
`date '2024-03-31' - 90` is 1 January 2024: subtracting an integer from a
`date` counts days.

```sql file=n08.sql
CREATE TABLE book (
  id integer PRIMARY KEY,
  title text NOT NULL,
  stock integer NOT NULL CHECK (stock >= 0)
);
CREATE TABLE orders (
  id integer PRIMARY KEY,
  placed date NOT NULL,
  status text NOT NULL
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id),
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
CREATE FUNCTION line_takes_stock() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE book SET stock = stock - NEW.qty WHERE id = NEW.book_id;
  RETURN NEW;
END;
$$;
CREATE TRIGGER line_takes_stock
AFTER INSERT ON order_line
FOR EACH ROW
EXECUTE FUNCTION line_takes_stock();
INSERT INTO book VALUES
  (1, 'Dune', 10), (2, 'Emma', 5), (3, 'Hobbit', 8), (4, 'Neuromancer', 3);
INSERT INTO orders VALUES
  (1, date '2024-01-05', 'shipped'), (2, date '2024-02-11', 'shipped'),
  (3, date '2024-02-20', 'paid'), (4, date '2024-03-03', 'shipped'),
  (5, date '2024-03-15', 'cancelled'), (6, date '2024-03-20', 'open');
INSERT INTO order_line VALUES
  (1, 1, 1), (1, 2, 2), (2, 3, 1), (3, 1, 2),
  (4, 4, 1), (4, 3, 1), (5, 1, 5), (6, 2, 1);
.headers on
SELECT b.title, b.stock, coalesce(sum(l.qty), 0) AS sold_recent
FROM book b
LEFT JOIN order_line l ON l.book_id = b.id
LEFT JOIN orders o ON o.id = l.order_id AND o.status <> 'cancelled'
  AND o.placed >= date '2024-03-31' - 90
GROUP BY b.id
HAVING b.stock <= 5
ORDER BY b.stock, b.title;
```

```text output
title|stock|sold_recent
Dune|2|8
Emma|2|3
Neuromancer|2|1
```

## Cancel an open order and put the stock back

The trigger already took three copies: two on a shipped order, one on this
open order, so stock is 2. Cancelling does not run that trigger backwards.
Both writes belong in one transaction. A `DO` block is one statement, so a
failure in the second update rolls the first one back. In an application
you `BEGIN` and `COMMIT` the same two statements on one connection. Emma
goes from 2 to 3. Do both writes or neither.

```sql file=n10.sql
CREATE TABLE book (
  id integer PRIMARY KEY,
  title text NOT NULL,
  stock integer NOT NULL CHECK (stock >= 0)
);
CREATE TABLE orders (
  id integer PRIMARY KEY,
  status text NOT NULL
);
CREATE TABLE order_line (
  order_id integer NOT NULL REFERENCES orders (id),
  book_id integer NOT NULL REFERENCES book (id),
  qty integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
CREATE FUNCTION line_takes_stock() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
  UPDATE book SET stock = stock - NEW.qty WHERE id = NEW.book_id;
  RETURN NEW;
END;
$$;
CREATE TRIGGER line_takes_stock
AFTER INSERT ON order_line
FOR EACH ROW
EXECUTE FUNCTION line_takes_stock();
INSERT INTO book VALUES (2, 'Emma', 5);
INSERT INTO orders VALUES (1, 'shipped'), (6, 'open');
INSERT INTO order_line VALUES (1, 2, 2), (6, 2, 1);
DO $$
BEGIN
  UPDATE orders SET status = 'cancelled' WHERE id = 6 AND status = 'open';
  UPDATE book SET stock = stock + (
    SELECT qty FROM order_line WHERE order_id = 6 AND book_id = book.id
  ) WHERE id IN (SELECT book_id FROM order_line WHERE order_id = 6);
END;
$$;
.headers on
SELECT title, stock FROM book WHERE id = 2;
```

```text output
title|stock
Emma|3
```

```sql file=exercise.sql
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  country text NOT NULL
);
CREATE TABLE book (
  id integer PRIMARY KEY,
  title text NOT NULL,
  genre text NOT NULL,
  price_cents integer NOT NULL
);
CREATE TABLE orders (
  id integer PRIMARY KEY,
  customer_id integer NOT NULL REFERENCES customer (id),
  placed date NOT NULL,
  status text NOT NULL
);
CREATE TABLE order_line (
  order_id integer REFERENCES orders (id),
  book_id integer REFERENCES book (id),
  qty integer NOT NULL,
  unit_price_cents integer NOT NULL,
  PRIMARY KEY (order_id, book_id)
);
```

```sql file=solution.sql
CREATE VIEW revenue_orders AS
  SELECT o.id AS order_id, c.name AS customer, sum(l.qty * l.unit_price_cents) AS total_cents
  FROM orders o
  JOIN customer c ON c.id = o.customer_id
  JOIN order_line l ON l.order_id = o.id

  GROUP BY o.id, c.name;

CREATE VIEW q1 AS
  SELECT c.country, sum(r.total_cents) AS cents

  SELECT c.name, min(o.placed) AS first_order
  FROM customer c
  LEFT JOIN orders o ON o.customer_id = c.id
  GROUP BY c.id
  ORDER BY c.name;
```
