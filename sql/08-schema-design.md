# SQL 08 — Schema Design: Tables, Keys, Constraints

Good schemas make bad data impossible. Put rules in the database (`NOT NULL`,
`UNIQUE`, `CHECK`, foreign keys, types) so every program that touches it
obeys them. Name tables and columns consistently: singular nouns,
`snake_case`, `thing_id` for foreign keys. Add `NOT NULL` unless NULL means
something. Change schemas with numbered migration scripts in version
control, not by hand (lesson 14).

Prefer a surrogate `int GENERATED BY DEFAULT AS IDENTITY` or a UUID as the
primary key, or a natural key you are sure will never change. Emails,
names, and phone numbers change. Do not use them as primary keys. Store
money as integer cents, or as `numeric`, never as `float8`:
`0.1::float8 + 0.2::float8` is not `0.3`. A bare `0.1` is already `numeric`.
Store calendar days as `date` and instants as `timestamptz`.

## Foreign keys are enforced

An insert whose `author_id` matches no author fails. You do not turn that
on per connection. `ON DELETE NO ACTION` is the default: the check runs at
the end of the statement, and a parent with children cannot disappear.

```sql file=n01.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text
);
CREATE TABLE book (
  author_id int REFERENCES author (id),
  title text
);
-- expect-error
INSERT INTO book (author_id, title) VALUES (99, 'Orphan');
SELECT count(*) AS orphans FROM book;
```

```text output
Error: insert or update on table "book" violates foreign key constraint "book_author_id_fkey"
0
```

## Checks and keys reject bad rows

A column's type is a rule. `'abc'` is not an `int`. `CHECK` guards ranges.
`UNIQUE (author_id, title)` is a composite rule. The foreign key points at
`author(id)`. `ON DELETE RESTRICT` refuses to delete a parent that still
has children, and it refuses immediately rather than at the end of the
statement. Name the constraints you will see in error messages.

```sql file=n02.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL CONSTRAINT name_not_empty CHECK (length(name) > 0),
  email text CONSTRAINT email_unique UNIQUE
);
CREATE TABLE book (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  author_id int NOT NULL CONSTRAINT book_author_fk REFERENCES author (id) ON DELETE RESTRICT,
  title text NOT NULL,
  year int CONSTRAINT year_range CHECK (year BETWEEN 1400 AND 2100),
  price int NOT NULL DEFAULT 0 CONSTRAINT price_nonneg CHECK (price >= 0),
  UNIQUE (author_id, title)
);
INSERT INTO author (name, email) VALUES ('Le Guin', 'ursula@example.com');
INSERT INTO book (author_id, title, year, price)
SELECT id, 'The Dispossessed', 1974, 1299 FROM author WHERE name = 'Le Guin';
.headers on
SELECT title, year, price FROM book;
```

```text output
title|year|price
The Dispossessed|1974|1299
```

## Each constraint fails on its own terms

`-- expect-error` tells this course's runner that the next statement must
fail. An unknown `author_id` fails the foreign key. A repeated email fails
`UNIQUE`. A negative price and an empty name fail `CHECK`. `'abc'` in an
`int` column fails the cast before any check runs. A NULL name fails
`NOT NULL`. Deleting Le Guin fails `ON DELETE RESTRICT` while her book
exists.

```sql file=n03.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL CONSTRAINT name_not_empty CHECK (length(name) > 0),
  email text CONSTRAINT email_unique UNIQUE
);
CREATE TABLE book (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  author_id int NOT NULL CONSTRAINT book_author_fk REFERENCES author (id) ON DELETE RESTRICT,
  title text NOT NULL,
  year int CONSTRAINT year_range CHECK (year BETWEEN 1400 AND 2100),
  price int NOT NULL DEFAULT 0 CONSTRAINT price_nonneg CHECK (price >= 0),
  UNIQUE (author_id, title)
);
INSERT INTO author (name, email) VALUES ('Le Guin', 'ursula@example.com');
INSERT INTO book (author_id, title, year, price)
SELECT id, 'The Dispossessed', 1974, 1299 FROM author WHERE name = 'Le Guin';
-- expect-error
INSERT INTO book (author_id, title) VALUES (99, 'Orphan');
-- expect-error
INSERT INTO author (name, email) VALUES ('X', 'ursula@example.com');
-- expect-error
INSERT INTO book (author_id, title, price) VALUES (1, 'Free', -1);
-- expect-error
INSERT INTO author (name) VALUES ('');
-- expect-error
INSERT INTO book (author_id, title, year) VALUES (1, 'T', 'abc');
-- expect-error
INSERT INTO author (name) VALUES (NULL);
-- expect-error
DELETE FROM author WHERE name = 'Le Guin';
```

```text output
Error: insert or update on table "book" violates foreign key constraint "book_author_fk"
Error: duplicate key value violates unique constraint "email_unique"
Error: new row for relation "book" violates check constraint "price_nonneg"
Error: new row for relation "author" violates check constraint "name_not_empty"
Error: invalid input syntax for type integer: "abc"
Error: null value in column "name" of relation "author" violates not-null constraint
Error: update or delete on table "author" violates foreign key constraint "book_author_fk" on table "book"
```

## UNIQUE allows many NULLs

NULL means unknown, and unknown is not equal to unknown, so several missing
emails do not clash. `UNIQUE NULLS NOT DISTINCT` (PostgreSQL 15+) treats
NULLs as equal and rejects the second one. Add `NOT NULL` when a missing
value is not allowed at all. `coalesce` only changes what a query displays.

```sql file=n04.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  email text UNIQUE
);
INSERT INTO author (name, email) VALUES
  ('Le Guin', 'ursula@example.com'), ('Austen', NULL),
  ('Anon One', NULL), ('Anon Two', NULL);
SELECT count(*) AS authors FROM author;
.headers on
SELECT name, coalesce(email, '(none)') AS email FROM author ORDER BY name;
CREATE TABLE author_strict (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  email text CONSTRAINT email_once UNIQUE NULLS NOT DISTINCT
);
INSERT INTO author_strict (email) VALUES (NULL);
-- expect-error
INSERT INTO author_strict (email) VALUES (NULL);
```

```text output
4
name|email
Anon One|(none)
Anon Two|(none)
Austen|(none)
Le Guin|ursula@example.com
Error: duplicate key value violates unique constraint "email_once"
```

## ON DELETE CASCADE removes the children

A join table holds a many-to-many link and uses both ids as its primary
key. `ON DELETE CASCADE` deletes `book_tag` rows when the book goes.
`ON DELETE SET NULL` would keep the child and clear the foreign key, which
requires the column to allow NULL. Pick one on purpose: a careless
`CASCADE` is a mass delete.

```sql file=n05.sql
CREATE TABLE book (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL
);
CREATE TABLE tag (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL UNIQUE
);
CREATE TABLE book_tag (
  book_id int NOT NULL REFERENCES book (id) ON DELETE CASCADE,
  tag_id int NOT NULL REFERENCES tag (id) ON DELETE CASCADE,
  PRIMARY KEY (book_id, tag_id)
);
INSERT INTO book (id, title) VALUES (1, 'The Dispossessed');
INSERT INTO tag (id, name) VALUES (1, 'utopia'), (2, 'classic');
INSERT INTO book_tag VALUES (1, 1), (1, 2);
.headers on
SELECT count(*) AS links_before FROM book_tag;
DELETE FROM book WHERE id = 1;
SELECT count(*) AS links_after FROM book_tag;
```

```text output
links_before
2
links_after
0
```

## information_schema shows the schema

`information_schema.tables` lists tables in a schema. `public` is the
default schema. `information_schema.columns` lists each column's type,
whether it accepts NULL (`YES` or `NO`), and whether it is an identity
column. Constraints live in `information_schema.table_constraints` and in
`pg_constraint` when you need the delete rule or the check expression.

```sql file=n06.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  email text UNIQUE
);
CREATE TABLE book (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  author_id int NOT NULL REFERENCES author (id),
  title text NOT NULL,
  year int,
  price int NOT NULL DEFAULT 0
);
CREATE TABLE tag (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL UNIQUE
);
CREATE TABLE book_tag (
  book_id int NOT NULL,
  tag_id int NOT NULL,
  PRIMARY KEY (book_id, tag_id)
);
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public' AND table_type = 'BASE TABLE'
ORDER BY table_name;
.headers on
SELECT column_name, data_type, is_nullable, is_identity
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'book'
ORDER BY ordinal_position;
```

```text output
author
book
book_tag
tag
column_name|data_type|is_nullable|is_identity
id|integer|NO|YES
author_id|integer|NO|NO
title|text|NO|NO
year|integer|YES|NO
price|integer|NO|NO
```

## ALTER adds or renames a column

`ADD COLUMN` appends one. `RENAME COLUMN` keeps the data and changes the
name. The new `born` column is NULL until something fills it. Adding a
`NOT NULL` column to a table that already has rows requires a `DEFAULT`,
or the statement fails.

```sql file=n07.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL
);
INSERT INTO author (id, name) VALUES (1, 'Le Guin');
ALTER TABLE author ADD COLUMN born date;
ALTER TABLE author RENAME COLUMN name TO full_name;
SELECT full_name, born FROM author WHERE id = 1;
```

```text output
Le Guin|
```

## Normalise until each fact lives in one place

A book table that repeats `author_email` on every title copies the same
fact. Point `book.author_id` at `author` instead. Denormalise later only
when a measurement says the join is too slow.

```sql file=n08.sql
CREATE TABLE author (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  full_name text NOT NULL,
  email text
);
CREATE TABLE book (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  author_id int REFERENCES author (id),
  title text
);
INSERT INTO author (id, full_name, email) VALUES (1, 'Le Guin', 'ursula@example.com');
INSERT INTO book (id, author_id, title) VALUES (1, 1, 'The Dispossessed');
SELECT b.title, a.full_name
FROM author a
LEFT JOIN book b ON b.author_id = a.id
WHERE a.id = 1;
```

```text output
The Dispossessed|Le Guin
```

## Money is numeric or integer cents, not float8

Decimal literals are `numeric`, so `0.1 + 0.2` really is `0.3`. Cast to
`float8` and the binary fraction fails the equality. `pg_typeof` reports
the type. Store cents as `int`, or store a decimal price as `numeric`.
Add either with ordinary arithmetic. Booleans print as `t` and `f`.

```sql file=n09.sql
.headers on
SELECT (0.1 + 0.2) = 0.3 AS numeric_equal,
       (0.1::float8 + 0.2::float8) = 0.3::float8 AS float_equal,
       pg_typeof(0.1) AS literal_type,
       10 + 20 AS cents;
```

```text output
numeric_equal|float_equal|literal_type|cents
t|f|numeric|30
```

```sql file=solution.sql
CREATE TABLE student (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  email text UNIQUE
);
CREATE TABLE course (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL UNIQUE,
  credits int NOT NULL CHECK (credits BETWEEN 1 AND 6)
);
CREATE TABLE enrollment (
  student_id int NOT NULL REFERENCES student (id) ON DELETE CASCADE,
  course_id int NOT NULL REFERENCES course (id) ON DELETE RESTRICT,
  grade int CHECK (grade BETWEEN 0 AND 100),
  PRIMARY KEY (student_id, course_id)
);
```
