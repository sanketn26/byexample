# SQL 06 — Window Functions

`GROUP BY` collapses rows. A window function computes over related rows
and keeps every row. That gives rankings, running totals, previous-row
comparisons, and top-N per group without a self-join.

The shape is `function(...) OVER (PARTITION BY ... ORDER BY ... frame)`.
You cannot put a window function in `WHERE` or `HAVING`. Those clauses run
first. Filter in an outer query. `FILTER` on an aggregate limits which
rows the aggregate sees, and it works in a window too.

## An aggregate window keeps every row

`OVER ()` is the whole result. `PARTITION BY region` restarts the total
for each region. The row itself stays. `count(*) FILTER (WHERE ...)`
counts only the rows that pass, still without collapsing the partition.
`sum` of an `int` column is `bigint`.

```sql file=n01.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT rep, amount, sum(amount) OVER () AS grand_total,
       sum(amount) OVER (PARTITION BY region) AS region_total,
       count(*) FILTER (WHERE amount >= 100) OVER (PARTITION BY region) AS big_in_region
FROM sale ORDER BY id;
```

```text output
rep|amount|grand_total|region_total|big_in_region
ann|100|860|490|3
ann|150|860|490|3
bob|90|860|490|3
bob|150|860|490|3
cat|200|860|370|2
cat|50|860|370|2
dan|120|860|370|2
```

## rank, dense_rank, and row_number disagree on ties

`row_number` is unique. `rank` shares a place and leaves a gap (1, 1, 3).
`dense_rank` shares a place and does not leave a gap (1, 1, 2).
`row_number` over a tie is arbitrary unless `ORDER BY` includes a
tie-breaker such as `id`.

```sql file=n02.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT rep, amount,
       row_number() OVER (ORDER BY amount DESC, id) AS rn,
       rank()       OVER (ORDER BY amount DESC)     AS rnk,
       dense_rank() OVER (ORDER BY amount DESC)     AS dense
FROM sale ORDER BY amount DESC, id;
```

```text output
rep|amount|rn|rnk|dense
cat|200|1|1|1
ann|150|2|2|2
bob|150|3|2|2
dan|120|4|4|3
ann|100|5|5|4
bob|90|6|6|5
cat|50|7|7|6
```

## Top N per group is a rank you filter outside

`row_number` inside the partition, then `WHERE rn <= 1` in an outer query.
The window function is not allowed in the same query's `WHERE`. A derived
table needs an alias. The `id` tie-breaker makes "the" top sale
deterministic: ann's 150 beats bob's 150.

```sql file=n03.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT region, rep, amount FROM (
  SELECT region, rep, amount,
         row_number() OVER (PARTITION BY region ORDER BY amount DESC, id) AS rn
  FROM sale
) AS ranked
WHERE rn <= 1 ORDER BY region;
```

```text output
region|rep|amount
east|ann|150
west|cat|200
```

## ORDER BY inside OVER makes a running total

With `ORDER BY`, the default frame is "from the start through the current
row". Without it, the frame is the whole partition. That is why
`sum() OVER (ORDER BY ...)` grows row by row. Add a unique tie-breaker
(`day, id`) so two sales on the same day stay distinct.

```sql file=n04.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT day, amount, sum(amount) OVER (ORDER BY day, id) AS running
FROM sale WHERE region = 'east' ORDER BY day, id;
```

```text output
day|amount|running
2024-01-01|100|100
2024-01-01|90|190
2024-01-02|150|340
2024-01-03|150|490
```

## The default frame is RANGE, so ties are peers

Peers share one running total. `ORDER BY day` treats both January 1 sales
as the same position, and each of them sees 190. Say `ROWS BETWEEN
UNBOUNDED PRECEDING AND CURRENT ROW` when you want a row-by-row total
instead.

```sql file=n05.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT day, amount, sum(amount) OVER (ORDER BY day) AS running
FROM sale WHERE region = 'east' ORDER BY day, id;
```

```text output
day|amount|running
2024-01-01|100|190
2024-01-01|90|190
2024-01-02|150|340
2024-01-03|150|490
```

## lag and lead look at a neighbour

`lag(amount)` is the previous row in the window order, or NULL at the
start. `coalesce` of that NULL with the current amount makes the first
change zero. `lead` is the same idea, one row ahead.

```sql file=n06.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT day, amount,
       lag(amount) OVER (ORDER BY day, id) AS prev,
       amount - coalesce(lag(amount) OVER (ORDER BY day, id), amount) AS change
FROM sale WHERE region = 'west' ORDER BY day, id;
```

```text output
day|amount|prev|change
2024-01-01|200||0
2024-01-02|50|200|-150
2024-01-02|120|50|70
```

## A frame can be a fixed number of rows

`ROWS BETWEEN 1 PRECEDING AND CURRENT ROW` is this row and the one before
it. `round(..., 1)` keeps one decimal on a `numeric` average (`avg` of
`int` is `numeric`). This is a moving average, not a running total.

```sql file=n07.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT day, amount,
       round(avg(amount) OVER (
         ORDER BY day, id ROWS BETWEEN 1 PRECEDING AND CURRENT ROW), 1) AS avg2
FROM sale WHERE region = 'east' ORDER BY day, id;
```

```text output
day|amount|avg2
2024-01-01|100|100.0
2024-01-01|90|95.0
2024-01-02|150|120.0
2024-01-03|150|150.0
```

## first_value and a named window

`WINDOW w AS (...)` names a specification so two functions can share it.
`first_value` with `ORDER BY amount DESC` is the top rep in the region.
The percent uses a different window: the region total, with no order.
`100.0` makes the division `numeric` so the fraction is not truncated.

```sql file=n08.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT rep, amount,
       first_value(rep) OVER w AS top_rep,
       round(100.0 * amount / sum(amount) OVER (PARTITION BY region), 1) AS pct
FROM sale
WINDOW w AS (PARTITION BY region ORDER BY amount DESC, id)
ORDER BY region, amount DESC, id;
```

```text output
rep|amount|top_rep|pct
ann|150|ann|30.6
bob|150|ann|30.6
ann|100|ann|20.4
bob|90|ann|18.4
cat|200|cat|54.1
dan|120|cat|32.4
cat|50|cat|13.5
```

## last_value with the default frame is the current row

The default frame stops at the current row, so `last_value` is not the
end of the partition. Spell the frame out:
`ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`.

```sql file=n09.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT rep,
       last_value(rep) OVER (PARTITION BY region ORDER BY amount DESC, id) AS stopped_here,
       last_value(rep) OVER (
         PARTITION BY region ORDER BY amount DESC, id
         ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
       ) AS last_rep
FROM sale ORDER BY region, amount DESC, id;
```

```text output
rep|stopped_here|last_rep
ann|ann|bob
bob|bob|bob
ann|ann|bob
bob|bob|bob
cat|cat|cat
dan|dan|cat
cat|cat|cat
```

## ntile splits rows into buckets

`ntile(2)` puts the lower half in bucket 1. Extra rows go in the earlier
buckets, so four rows are in 1 and three are in 2.

```sql file=n10.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT rep, amount, ntile(2) OVER (ORDER BY amount, id) AS half
FROM sale ORDER BY amount, id;
```

```text output
rep|amount|half
cat|50|1
bob|90|1
ann|100|1
dan|120|1
ann|150|2
bob|150|2
cat|200|2
```

## Aggregate first, then rank the groups

A window runs after `WHERE` and `GROUP BY`. Collapse to one row per
region, then rank those rows. You cannot nest a window inside `sum`.
`string_agg(expr, ',' ORDER BY ...)` concatenates values inside the
group. The order belongs on the aggregate, not on a window: window
aggregates do not take `ORDER BY` inside the function call.

```sql file=n11.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT region,
       string_agg(rep, ',' ORDER BY amount DESC, id) AS reps,
       sum(amount) AS total,
       rank() OVER (ORDER BY sum(amount) DESC) AS place
FROM sale
GROUP BY region
ORDER BY place;
```

```text output
region|reps|total|place
east|ann,bob,ann,bob|490|1
west|cat,dan,cat|370|2
```

## lag finds consecutive repeats

Compare each amount with the previous one. Keep the row when there is no
previous amount, or when it changed. The second east sale of 150 drops out.

```sql file=n12.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);
.headers on
SELECT day, amount FROM (
  SELECT id, day, amount, lag(amount) OVER (ORDER BY day, id) AS p
  FROM sale WHERE region = 'east'
) AS steps
WHERE p IS NULL OR p <> amount
ORDER BY day, id;
```

```text output
day|amount
2024-01-01|100
2024-01-01|90
2024-01-02|150
```

```sql file=solution.sql
CREATE TABLE sale (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  rep text NOT NULL,
  region text NOT NULL,
  day date NOT NULL,
  amount int NOT NULL
);
INSERT INTO sale (rep, region, day, amount) VALUES
  ('ann', 'east', '2024-01-01', 100), ('ann', 'east', '2024-01-02', 150),
  ('bob', 'east', '2024-01-01',  90), ('bob', 'east', '2024-01-03', 150),
  ('cat', 'west', '2024-01-01', 200), ('cat', 'west', '2024-01-02',  50),
  ('dan', 'west', '2024-01-02', 120);

CREATE VIEW q1 AS
  SELECT id, round(100.0 * amount / sum(amount) OVER (PARTITION BY region))::int AS pct
  FROM sale ORDER BY id;
CREATE VIEW q2 AS
  SELECT region, rep, amount FROM (
    SELECT region, rep, amount, id,
           row_number() OVER (PARTITION BY region ORDER BY amount DESC, id) AS rn
    FROM sale
  ) AS ranked
  WHERE rn <= 2 ORDER BY region, amount DESC, id;
CREATE VIEW q3 AS
  SELECT id, sum(amount) OVER (ORDER BY day, id) AS running FROM sale ORDER BY day, id;
CREATE VIEW q4 AS
  SELECT id, delta FROM (
    SELECT id, amount - lag(amount) OVER (PARTITION BY rep ORDER BY day, id) AS delta
    FROM sale
  ) AS deltas
  WHERE delta IS NOT NULL ORDER BY id;
CREATE VIEW q5 AS
  SELECT amount, dense_rank() OVER (ORDER BY amount DESC) AS place
  FROM (SELECT DISTINCT amount FROM sale) AS amounts
  ORDER BY place;

CREATE TABLE grade (name text, ok boolean NOT NULL CHECK (ok));
INSERT INTO grade VALUES ('q1', (SELECT string_agg(id::text || ':' || pct::text, ',' ORDER BY id) FROM q1) = '1:20,2:31,3:18,4:31,5:54,6:14,7:32');
```
