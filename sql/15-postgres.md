# SQL 15 — PostgreSQL patterns

These are the PostgreSQL queries people look up after the basics. Each
one is a feature of PostgreSQL: `DISTINCT ON`, `ON CONFLICT`, `jsonb`,
`generate_series`, `FILTER`, and `LATERAL`.

## `DISTINCT ON` keeps the first row of each group

Sort so the row you want is first inside the group. `DISTINCT ON (city)`
then keeps that row and drops the rest. The `ORDER BY` must start with
the same expressions.

```sql file=n01.sql
CREATE TABLE reading (city text, recorded_at timestamp, temp numeric);
INSERT INTO reading VALUES
  ('Oslo', '2024-03-01 08:00', 2),
  ('Oslo', '2024-03-02 08:00', 5),
  ('Lagos', '2024-03-01 08:00', 31),
  ('Lagos', '2024-03-03 08:00', 33);
SELECT DISTINCT ON (city) city, recorded_at::date AS day, temp
FROM reading
ORDER BY city, recorded_at DESC;
```

```text output
Lagos|2024-03-03|33
Oslo|2024-03-02|5
```

## `ON CONFLICT` updates the row that is already there

The insert hits the primary key, so `DO UPDATE` adds the new amount to
the balance that is already stored. `EXCLUDED` is the row that was
rejected. `RETURNING` gives back the row after the update.

```sql file=n02.sql
CREATE TABLE account (id int PRIMARY KEY, balance int NOT NULL);
INSERT INTO account VALUES (1, 10);
INSERT INTO account (id, balance) VALUES (1, 5)
ON CONFLICT (id) DO UPDATE SET balance = account.balance + EXCLUDED.balance
RETURNING id, balance;
```

```text output
1|15
```

## `jsonb` stores a document you can index

`->>` returns text. `@>` asks whether the left document contains the
right one. `jsonb` is the binary form; prefer it over `json`.

```sql file=n03.sql
SELECT '{"name":"Ada","tags":["db","sql"]}'::jsonb ->> 'name' AS name;
SELECT '{"tags":["db","sql"]}'::jsonb @> '{"tags":["db"]}'::jsonb AS has_db;
```

```text output
Ada
t
```

## `date_trunc` and `generate_series` build time buckets

`date_trunc('month', ...)` is the first instant of that month.
`generate_series` walks from a start to a stop by an interval.

```sql file=n04.sql
SELECT date_trunc('month', timestamp '2024-03-15 13:45') AS month_start;
SELECT d::date
FROM generate_series(date '2024-03-01', date '2024-03-03', interval '1 day') AS d;
```

```text output
2024-03-01 00:00:00
2024-03-01
2024-03-02
2024-03-03
```

## `FILTER` keeps rows out of one aggregate

`string_agg` joins values in order. `FILTER (WHERE status = 'paid')`
drops the void sale before the aggregate sees it. A rep with no paid
row produces NULL.

```sql file=n05.sql
CREATE TABLE sale (rep text, amount int, status text);
INSERT INTO sale VALUES
  ('Ada', 10, 'paid'), ('Ada', 3, 'paid'), ('Ada', 4, 'void'), ('Bea', 7, 'paid');
SELECT rep,
       string_agg(amount::text, ',' ORDER BY amount) FILTER (WHERE status = 'paid') AS paid
FROM sale
GROUP BY rep
ORDER BY rep;
```

```text output
Ada|3,10
Bea|7
```

## `LATERAL` runs a subquery for each outer row

The inner query sees `b.id`. `LEFT JOIN LATERAL ... ON true` keeps a
book that has no notes; the note column is NULL. `LIMIT 1` is the
first note in alphabetical order.

```sql file=n06.sql
CREATE TABLE book (id int PRIMARY KEY, title text);
CREATE TABLE note (book_id int, body text);
INSERT INTO book VALUES (1, 'A'), (2, 'B');
INSERT INTO note VALUES (1, 'one'), (1, 'two');
SELECT b.title, n.body
FROM book b
LEFT JOIN LATERAL (
  SELECT body FROM note WHERE book_id = b.id ORDER BY body LIMIT 1
) n ON true
ORDER BY b.title;
```

```text output
A|one
B|
```

## `ILIKE` matches without caring about case

`%` is still "anything". `ILIKE` is the case-insensitive form of
`LIKE`. It is PostgreSQL, not standard SQL.

```sql file=n07.sql
SELECT 'PostgreSQL' ILIKE 'post%' AS prefix;
```

```text output
t
```

## `IDENTITY` numbers the rows

`GENERATED BY DEFAULT AS IDENTITY` fills `id` when the insert omits it.
You can still supply an id. `GENERATED ALWAYS` refuses an explicit id
unless you say `OVERRIDING SYSTEM VALUE`.

```sql file=n08.sql
CREATE TABLE city (
  id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name text
);
INSERT INTO city (name) VALUES ('Oslo'), ('Lagos');
SELECT id, name FROM city ORDER BY id;
```

```text output
1|Oslo
2|Lagos
```

## Exercises

Each exercise is a view. The check stops at the first wrong answer.

```sql file=exercise.sql
CREATE TABLE reading (city text, recorded_at timestamp, temp int);
INSERT INTO reading VALUES
  ('Oslo', '2024-03-01', 2),
  ('Oslo', '2024-03-02', 5),
  ('Lagos', '2024-03-01', 31),
  ('Lagos', '2024-03-03', 33);

-- q1: one row per city, the latest temp. Columns city, temp.
--     Use DISTINCT ON. Order so the newest reading is first.
CREATE VIEW q1 AS SELECT 'nope'::text AS city, 0 AS temp;

CREATE TABLE t (name text, ok boolean CHECK (ok));
INSERT INTO t VALUES (
  'latest',
  (SELECT string_agg(city || ':' || temp::text, ',' ORDER BY city) FROM q1)
    = 'Lagos:33,Oslo:5'
);
SELECT 'PASS ' || name FROM t;
```

<details><summary>Solution</summary>

```sql file=solution.sql
CREATE TABLE reading (city text, recorded_at timestamp, temp int);
INSERT INTO reading VALUES
  ('Oslo', '2024-03-01', 2),
  ('Oslo', '2024-03-02', 5),
  ('Lagos', '2024-03-01', 31),
  ('Lagos', '2024-03-03', 33);

CREATE VIEW q1 AS
  SELECT DISTINCT ON (city) city, temp
  FROM reading
  ORDER BY city, recorded_at DESC;

CREATE TABLE t (name text, ok boolean CHECK (ok));
INSERT INTO t VALUES (
  'latest',
  (SELECT string_agg(city || ':' || temp::text, ',' ORDER BY city) FROM q1)
    = 'Lagos:33,Oslo:5'
);
SELECT 'PASS ' || name FROM t;
```
